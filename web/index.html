How LineTwin works — read this first

A live simulation of a 30-station vehicle assembly line (12 body · 6 paint · 12 final assembly) running right now in a real Python process — nothing here is pre-recorded. Every number updates 8×/second.

  • Bottleneck detection — the Active Period Method names whichever station has been continuously busy the longest (§ Bottleneck card).
  • Defect-risk scoring — a trained model scores every station's risk right now from live queue pressure and cycle-time signals (§ station tiles).
  • Sensor-gap inference — 8 of 30 stations have no sensor. Their values are solved live from a graph equation over their neighbours and tagged inferred — N%, never shown as if measured (§ station tiles).
  • Rolling-horizon prediction — every second the server forks the line's current state and fast-forwards ~30 simulated minutes to forecast where the bottleneck is headed (§ Plant Manager tab).
  • Defect genealogy — tracing a flagged defect back to its likely origin station. Built and tested (src/twin/diagnostic/genealogy.py), run on demand against the event log, not wired into this live view.

Try this → in the Perturbation panel below, pick a station and a cycle-time multiplier, then Apply. Watch the Bottleneck card, charts, and Alerts respond within a couple of seconds.

Live alerts

How this works
  • Computed client-side from the same stream every panel reads — nothing extra runs server-side.
  • Every alert says why and how confident, never a bare red flag — false alarms erode trust.
  • Bottleneck shift — the live verdict changed station. Tagged provisional or established.
  • Risk flag — a station's risk score crossed the model's own tuned threshold. Fires once per rising edge, not every tick.
  • Sustained disruption — BLOCKED or STARVED for many ticks in a row — a real ongoing effect, not a blip.

Bottleneck

How this works
  • Active Period Method — every station tracks how long it's been continuously "active" (working, or stopped for a reason that isn't its own fault). The longest current active streak is the bottleneck.
  • Benchmarked against 5 alternative methods on this line and won — 100% top-1 accuracy against ground truth from a separate sensitivity analysis.
  • Confidence — provisional: the gap over the runner-up isn't yet statistically clear. established: it is. Shown as a caveat, never used to suppress or delay detection.

Perturbation

How this works
  • The one control that actually changes the live simulation — multiplies one station's cycle time going forward.
  • A part already mid-cycle finishes at its original speed — a real machine wouldn't jump speed mid-part either.
  • Everything else on this page is read-only, watching the effect ripple through.

Line trend

How this works
  • Throughput (UPH) — units/hour the whole line is completing, averaged across all 30 stations. One slow station drags this down even if the other 29 are fine.
  • WIP — units sitting in buffers between stations, summed line-wide. Rising WIP is the earliest visible sign of a new bottleneck.

Predicted downtime

How this works
  • Once a second, the server copies the line's current state (busy/blocked/starved, queue levels, any perturbation applied).
  • Fast-forwards that copy ~30 simulated minutes on an independent random sequence — a "what happens if this keeps going" projection, not a claim of replaying the real future.
  • Re-diagnosed the same way the live bottleneck is.
