End-of-project checklist

Verified before submission

A · Deliverable coverage

What Round 2 actually asked for.

  • Runs from a clean clone with one documented command
  • Demonstrates the core predictive mechanism live, not a scripted playback
  • Runs on illustrative data, and says so plainly
  • Business Proposal inputs handed over — roadmap, risks, ROI, target users
  • Pitch assets handed over — video, screenshots, run steps

B · Every complexity answered

Each one locatable in the running system, not just the README.

  • Uneven sensor coverage → inference + degradation curve
  • Multi-causal root causes → drivers labelled associative, not causal
  • Legacy PLC / OT → read-only tap, never in the control path
  • Late-surfacing defects → genealogy with transfer-delay realignment
  • Three personas → three views over one model
  • Scaling across sites → config only, no new code
  • False alarms erode trust → significance gate + calibration

C · Nothing overstated

The discipline that makes the rest of it credible.

  • Every metric names the unseen configuration it was evaluated on
  • Thresholded metrics always printed with their threshold
  • Baseline published beside the model, whatever the lift
  • Measured values distinguished from model-computed ones
  • Positioned honestly — no standards-compliance or millisecond-fidelity claims
  • No flagged third-party figure repeated as our own or as verified
  • Patent cited as claims, never demonstrates
  • Synthetic parameters labelled; calibrated ones carry a source

D · Verification

Claims that a reviewer can re-run themselves.

  • Twenty or more tests green; CI green on both operating systems
  • Both silent-bug regressions fail red when their guard is removed
  • Same seed reproduces exactly; a different seed diverges
  • Analytics path runs with the simulation library unimported
  • Fresh-machine clean-clone test passed by someone else
  • All three falsifiability beats recorded
